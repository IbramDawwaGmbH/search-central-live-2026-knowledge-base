Summary

Key takeaways

Day 2 followed a fetched page into the index. Most of what decides whether it is indexed, and how it is shown, in AI answers too, happens there.
  1. Rendering is a separate, expensive pass.Every 200 page without noindex is queued for a detached render. Put what indexing needs in the server HTML.
  2. Googlebot neither clicks nor scrolls.Content behind a click or a scroll listener never loads. The viewport is about 10,000 pixels tall.
  3. A robots.txt block is not a noindex.noindex works only on a page Google may crawl, and removing it with JavaScript doesn't work.
  4. Snippet rules are now AI rules.nosnippet and max-snippet also limit AI Overviews and AI Mode, which are built from snippets.
  5. Where text sits matters; chunking doesn't.Footer words weigh less than main content. Gemini reads millions of tokens; 100-word chunks miss the point.
  6. Duplicates become one representative plus alternate names.One URL per cluster is indexed and gets the others' signals; old domains in site: queries are alternate names.
  7. Google decides the canonical.rel=canonical is often wrong, so it is one input. When your signals disagree, Google can't tell what you want.
  8. Structured data is still the precise, cheap route.Google prefers markup to LLM extraction, and the same data feeds AI features. There is no special AI markup.
  9. hreflang fails on small mistakes.Every page needs a self-reference, return links and ISO codes: sv not se, GB not UK, never EU.
  10. Index selection is a quality gate.'Crawled – currently not indexed' is mostly about quality; 'Discovered' means Google doesn't want to crawl it yet.
  11. There is no separate AI index.AI Overviews and AI Mode query the same index and use the same token-based snippets as web results.
  12. A video needs a watch page and a visible player.Without a watch page, or below the fold, it isn't indexed, Gary Illyes said. The docs want the player at load.
  13. Consolidate by intent; never redirect to the homepage.Merge pages that serve one intent and redirect only to a same-intent page. Removed URLs get a 404 or 410.
  14. Google Trends shows share, not volume.A line falling since 2004 can hide rising searches. Compare terms in one chart; take volumes elsewhere.

From HTML to extracted elements

Processing starts with the HTML the crawler fetched. Google parses it into a DOM, tells header, navigation and main content apart, and extracts the elements site owners add for indexing.

Put rel=canonical and hreflang in the head of the HTML your server sends, not only in JavaScript-rendered HTML. Google reads them while parsing, without waiting for rendering.

Links Google can and cannot extract

<!-- Google can extract -->
<a href="https://example.com/products">
<a href="/products">

<!-- Google cannot extract (slide) -->
<a onclick="goTo('products')">
<span href="/products">
<a routerLink="/products">
<a href="javascript:goTo('products')">

Slide An a element with an href, absolute or relative, is the normal way to link. An onclick handler never runs because Googlebot does not click, and href on a span is not a standard link.

Docs Google's link guide calls these patterns not recommended and notes that Google may still try to parse them.

Analysis The slide is stricter than the docs. Either way, none of them is a link you can rely on for discovery.

Stage Google sometimes extracts URLs typed as plain text (not in docs; partly unclear in the recording). Analysis Don't count on it.

Analysis

Audit every template and component that outputs links: navigation, pagination, filters, product tiles, language selectors. Each needs a real a element with an href; anything else leaves the target pages without a link Google can rely on.

Four questions from the welcome Q&A

Day 1's leftover questions, answered on slides, then on stage, by Gary Illyes and Cherry Prommawin.

robots.txt and noindex
Why isn't a disallow treated as noindex?
Slide "Simply put, it's because of sites that are extremely important and like to disallow their most important pages, either accidentally or out of ignorance." (not in docs) Disallowed content isn't indexed, but the URLs can still appear. Stage A national tax authority blocking its key PDFs still gets their URLs shown (the example not in docs). Docs A crawler that can't fetch a page never sees its noindex. Analysis robots.txt for crawling, noindex for indexing.
HTML sitemaps
Do they still help large sites?
Slide Good ones are hard to make for large sites: "Better rely on hubs like category pages that link out to your important pages." Stage "if you want to make one, knock yourself out". Docs Google's ecommerce guide: menus to categories to products, plus a sitemap or Merchant Center feed. Analysis Google's line has moved since a 2005 post that encouraged HTML sitemaps.
Out of stock
Keep the page or redirect it?
Slide "It depends on the importance of the PDPs to the users." Some users wait months, or pre-order. Stage A rare watch battery is worth the wait; a cheese is simply swapped (not in docs). Docs A 302 keeps the source URL in results. Analysis Keep the page live with a 200 and current availability in Product markup; redirect only if users would rather switch than wait.
Sitemaps
List them in robots.txt?
Slide "If it's included in the robots.txt file, any crawler can pick your sitemaps up". A sitemap not listed there has to be submitted instead, for example in Search Console. Stage "you can include it in robots.txt. No problem whatsoever." The trade-off: anyone can then see the sitemap.

Section 03 · John Mueller, Search Relations Team Lead

Controlling indexing

robots.txt controls crawling, not indexing. Robots meta tags control whether a page is indexed and how it is shown, and some of them now also decide what AI Overviews and AI Mode may use.
"You can use robots meta tags to be more visible in Search results than without robots meta tags."True or false? John Mueller's opening quiz. His answer: true

Slide The tag sits in the head and gives page-specific instructions: <meta name="robots" content="rule1,rule2">, or with the name googlebot instead of robots. Docs Google also respects robots meta tags placed in the body.

Analysis Before adding nosnippet or a low max-snippet, weigh the cost in AI features as well as in classic results.

The recommendation for maximum visibility

Slide "To be as visible as possible in Google, use: max-image-preview:large, max-snippet:-1"

Analysis Set both on every indexable template unless licensing forbids it, and check that no CMS, plug-in or CDN adds lower limits.

Robots rules, JavaScript and AI crawlers

Stage Robots meta rules only work if robots.txt lets Google fetch the page. A blocked page's URL can still be indexed; its content can't.

Slide Rules can be added with JavaScript, but it takes longer, and removing a noindex that way doesn't work. Stage When Google sees a noindex in the HTML, "we won't even process the JavaScript". Put robots meta tags in the HTML exactly as intended; use JavaScript only where nothing else is possible, as in a JavaScript web app. Docs Google says it may skip rendering on a noindex page. Analysis Never serve a noindex that a script is meant to lift.

Stage "AI crawlers don't really know what to do with a nofollow link, because they're looking at the content" (not in docs). Analysis nofollow is no access control: use robots.txt per crawler, Google-Extended for Gemini, the Search generative AI setting for AI features.

Stage robots.txt has an RFC (9309, co-authored by Gary Illyes); robots meta tags have none yet, and Mueller invited the room to help write one.

Section 04 · Erin Sparling · Lightning session D

Rendering and JavaScript

Google renders nearly all of the web with a real browser engine, in a detached system that is expensive to run. If content is not in the final DOM, Google can't see it.

Slide "Rendering Pages to Index What Users See." Stage In Erin Sparling's words, "our mission is very simple these days: execute JavaScript"; the implementation is complex and expensive (not in docs).

Docs Every page with a 200 status goes to the render queue unless a robots rule says not to index it. Stage Content indexable without JavaScript "can pass through" (not in docs). Analysis It doesn't wait for the slower pass; the page is still rendered.

Stage Gemini training reuses Search's rendering: "if it works for Search, it works for Gemini for training", if the site allows training on its content. A page a Gemini user asks about is read live, which takes time, so render fast or on the server (not in docs). AI Overviews and AI Mode typically don't read pages live to ground their answers.

Section 05 · Gary Illyes

Understanding what's on a page

Google weighs words by where they sit, stores pages as tokens rather than text, and detects soft 404s with a model that reads layout as well as language.

The main content carries the weight

Slide On Google's example blog page, the header and navigation were marked as not so important and the main content as very important: the post title and opening sentence counted; the tagline and the categories sidebar were supplementary.

Stage Gary Illyes's definition: "Main content is any part of the page that directly helps the page achieve its purpose". It is not only text: images, videos, a tool, user-generated content, the comments below a post, tab content, every heading and the visible title can all be part of it. What sits in the navigation or header tells Google the site doesn't particularly care about it. And "It's the main content that we consider for ranking."

Docs The Search Quality Rater Guidelines give the same definition; tabs, reviews and comments count as main or supplementary content depending on the page's purpose.

Stage Words get different weights depending on the part of the page they sit in: "if you put something in a footer, it's more likely that it's not going to contribute much to ranking" (not in docs). The simplest way to make a word count is to move it into the main content, because "where you position text on a page will already contribute quite a bit to ranking that page". And not everything can be main content: then nothing would stand out.

Docs Google's canonicalization guide calls it the primary content, or centerpiece, and clusters pages whose centerpiece matches. Stage Illyes pointed to the Search Quality Rater Guidelines as the detailed reference. Analysis Put the terms a page should rank for in its title, headings and opening paragraphs, not in footer or sidebar blocks.

Tokens, not pages

Stage The Search index doesn't store sentences or HTML. Text is cut into the smallest units that can still be searched: words, for languages written with spaces; statistically segmented words for Thai and Chinese, with exactly the same segmentation applied to queries (not in docs).

Stage Each token carries metadata for ranking: whether it appeared in the header or the main content ("centerpiece"), in bold or in a heading, plus spam markers such as white text on a white background (not in docs). Analysis Leftover hidden keyword blocks are a liability, not neutral clutter.

Stage Tokenization for AI models such as Gemini, in training and in inference, differs from tokenization for Search, "or mostly" (not in docs). Analysis Day 1's slide said Gemini shares tokenization with Search. Read it as a shared step with different outputs.

The chunking myth

Stage The advice to chunk content for AI is misunderstood. Chunking is real, but it matters at the level of a model's context window, and Gemini's holds millions of tokens (Illyes also put it at 900,000 to a million). Gemini doesn't need 100- or 200-word chunks; thought of in millions of tokens, chunking has perhaps lost its meaning anyway (that last point not in docs).

Analysis Don't rewrite pages into short, self-contained chunks. Write for readers: clear headings, complete explanations. Google's long-context docs say 1 million tokens or more: plan with one million as the floor.

How Google spots a soft 404

Stage A soft 404 should return an error but returns 200, and because error pages are worded in endless ways, keyword matching can't find them (not in docs). Slide Four common causes: pages that look like errors but aren't, thin or empty content, server or CMS misconfiguration, and JavaScript content that fails to load. Plus a bonus: "Mistakes in Google's systems (that you should notify us about)".

Stage Detection uses a model, "something like BERT, that is specifically trained to understand page structure". Position decides: an error in the navigation need not make a soft 404, but an error alone in the main content does (not in docs).

Analysis Return real status codes for error states, also in single-page apps: 404 or 410 for missing content, 503 for outages such as a failed database connection.

Section 06 · Handling web duplication · John Mueller · Lightning session E

Duplicates and canonicals

Google clusters equivalent URLs, indexes one representative and forwards the others' signals to it. Which URL represents the cluster is Google's call; your signals only steer it.

Stage John Mueller gave two reasons to deduplicate: users don't want the same page ten times; and room: the index can't hold everything, storage has many competing uses and its price has risen sharply (that last point not in docs). A site migration is simply deduplication across sites: the owner says the old and the new domain are the same, and that Google should pick the new one.

How clusters form

InputWhat Google said
RedirectsStage Trusted very much: a clear sign there is one version. And "the permanent redirect really only matters for canonicalization, not for clustering." Docs With a 302, Search keeps showing the source URL. Analysis Use 301 or 308 for moves you want reflected.
ContentStage Exact matches (www and non-www), near matches, structurally similar content and soft 404s (the four-way split is not in docs). Slide Translated menu and footer around an untranslated main text: "When main content is the same, pages may be clustered."
rel=canonicalStage Probably the most common signal, and very often wrong, for example a placeholder value instead of a real URL (partly unclear in the recording). So Google makes its own judgement.
"Magic bucket"Stage Everything else.

When a URL pattern decides

Slide If /buy/fax, /buy/typewriter and /office-equipment show the same content, Google's systems may assume every /buy/ URL does: "Do we even need to crawl /buy/seo-service ?" A car dealer's near-identical city pages can be folded into one city the same way (not in docs). The advice: avoid many similar-looking URLs with the same content, and return errors for URLs that no longer exist. Docs To split a wrong cluster, make the pages clearly different; Google may keep them clustered for up to two weeks after the fix.

Bot walls make duplicates

Stage A CDN challenge page shown to Googlebot on many URLs or domains gets them clustered as duplicates; Google struggles to recognise such pages as errors and can't solve the puzzles. AI agents browsing for users hit the same walls and may buy elsewhere (not in docs). Docs Google's CDN post: such pages may be dropped as duplicates and recover slowly; send crawlers a 503.

Choosing the representative

Stage Many criteria, weighted by machine learning: "we use some kind of machine learning to understand how strong these criteria should be. And this changes from time to time." (not in docs)

Hijacking
Slide Several domains claiming the same content: your own staging copy, or third parties, malicious or not. Report cases Google gets wrong.
User experience
Slide The page must load: a broken certificate, failing JavaScript or a page that can't load counts against a URL. The slide also lists meta refresh and security.
Site-owner signals
Slide Redirects, only the preferred URL in sitemaps, and rel=canonical, which "also helps a bit". Docs Redirects and rel=canonical are strong signals; sitemaps weak.

Stage When every signal points the same way, Google follows the owner; but "if there are multiple things in different directions, we don't know what to do." Analysis Before a migration or template change, align redirects, rel=canonical, internal links, sitemaps, hreflang and working HTTPS.

Same language, different countries
Slide German pages for Germany, Austria and Switzerland are tricky to deduplicate. "We try to use hreflang alternates." Avoid "clever" geo-redirecting. Docs Pages in hreflang clusters are preferred as canonicals. Analysis Use de-DE, de-AT, de-CH and make the pages differ in more than boilerplate.
Old domains after a migration
Slide Alternate names are why site: queries still show an old domain, which owners misread as a failed move. Someone searching an old brand may see the old URL. Stage The redirect takes them on. Docs "This is normal and as users get used to the new domain name, the alternate names will fade away without you doing anything." Analysis Judge the move in Search Console; keep redirects long term.

Stage Pointing a paginated series' canonicals to page 1 can sometimes make sense, for example to strengthen a category page (not in docs). Docs Google's 2013 post calls it incorrect: later pages' content would not be indexed. Analysis Keep self-referencing canonicals unless you deliberately want later pages folded into page 1.

Slide The closing list: use redirects for migrations, use HTTP result codes, "Don't block agents.", check your rel=canonical links, use hreflang to help Google localise, report weird canonicals in the forums, make secure pages that work, and keep canonical signals clear.

Merging two competing sites · Martyna Ağanoğlu, Loando

Stage Two of Poland's first loan-comparison sites did exactly the same thing and competed for the same users, keywords and results. After an acquisition by a group active in eleven markets, they became one brand. Three goals came before any technical work: lower costs, one strong brand, and a simple structure instead of hundreds of similar URLs competing with each other.

Stage Both domains were checked for past penalties and compared on traffic, conversion and revenue before one was chosen. Removed URLs got an error status; none went to the homepage, even those still bringing traffic. Then: new sitemaps, a change of address in Search Console, internal links pointing at the new pages, merged analytics, the financial experts behind the site introduced, and Search Console checked daily against the old baseline for months. Docs Google's site move guide lists the same three technical steps.

Stage Traffic grew from the first day, with no dip; revenue grew 100% month over month (the speaker's figure, period not stated). Docs Don't redirect many old URLs to one irrelevant page such as the homepage; return 404 or 410 for content that isn't moved. Analysis Which of the two codes matters less than not redirecting to an unrelated page. At about 2,000 URLs crawl budget is hardly the gain; one strong URL per intent, with its signals consolidated, is.

Section 07 · Finding the gold nuggets · Lightning session F

Feature extraction: structured data, images, video

After deduplication, Google pulls the "gold nuggets" out of each page: structured data, images and videos. Markup is still the precise, cheap route, and Google says it will keep preferring it.

Stage A dedicated system, whose internal name Gary Illyes wouldn't share, does the expensive extraction, and it runs after deduplication so the work is spent on a trimmed set of documents (not in docs). Docs Google's guidelines: "we recommend placing the same structured data on all page duplicates, not just on the canonical page". Analysis Markup that exists only on a duplicate that loses canonical selection may never be extracted.

Why structured data still matters

Stage Ryan Levering, a Google software engineer who works on data ingestion, described two camps inside Google: markup is useless because models can read pages, or markup is the future of machines talking to each other. The truth, he said, is in the middle. Slide Four reasons it still matters:

Precision
Slide Higher accuracy than large-scale LLM extraction for complex schema such as sale pricing. Stage In his tests LLMs invented properties and got nested pricing wrong (not in docs).
Extra content
Slide Metadata the page text lacks, such as full ISO dates (Google may misread a visible date's time zone) or stable IDs. Docs Still only for content users can see.
Efficiency
Stage Even Google can't run complex models on every page; parsing markup is nearly free: "So we're always going to prefer that particular approach." (not in docs)
Focus
Slide Markup points at the pertinent data, so Google doesn't pick up, say, a related product's price (not in docs).

Stage The same processed markup feeds classic results and AI Overviews and AI Mode. Raw schema.org is generally not put straight into a model's context: it is sorted, checked and indexed first, partly because raw markup would be an abuse vector (not in docs). Docs Google's guide to generative AI features lists overfocusing on structured data among things not needed; it still helps rich results. Analysis Skip markup written for AI; implement the types Google documents.

What Google recommended

  • Stage JSON-LD, microdata and RDFa enter the same pipelines; JSON-LD is recommended because people make fewer mistakes with one block. Microdata saves page weight (not in docs).
  • Stage "we will never penalize you for having more structured data on your pages", but irrelevant markup can be treated as abuse. Docs A manual action removes rich results, not rankings.
  • Stage A common fault: two plug-ins emit the same type, and an event page reads like a list of events (not in docs). Analysis Test one page per template.

Language, country and hreflang

Google reads a page's language from its content and records one language per page. hreflang only maps equivalent versions to audiences, and it fails on small mistakes.

Stage Working out a site's localised pages and target countries is one of the complex tasks of indexing, Google said, and started with the basics: Google may find language versions on its own, but each needs its own URL; switching languages by cookie or by swapping content in place makes them very hard to handle. Docs Googlebot mostly crawls from US IP addresses and sends no Accept-Language header.

The mistakes Google sees most

  • Slide "If page X links to page Y, page Y must link back to page X." Stage One-way pairs are ignored, or anyone could claim to be your language version.
  • Stage No self-reference: every page must list its own URL too.
  • Stage Two or three methods at once, conflicting. Docs HTML head, HTTP header and sitemap are equivalent; pick one.
  • Docs Alternate URLs must be fully qualified, protocol included.

Stage A ccTLD is one of the strongest country signals; server location (an unclear word in the recording) is not really reliable nowadays (not in docs). Analysis A second recording heard "IP address" for the strongest signal; the docs back the ccTLD. Stage AI Overviews and AI Mode need no extra work: they sit on top of web results. But in classic results users notice missing or poorly translated content; AI answers synthesise it away, "an invisible gap". And "AI is still language-dependent": a query in another language draws on different data.

Analysis Test AI answers with native-language queries in each market, and compare with the country breakdown of Search Console's generative AI report.

Section 10 · How does the index look like?

Inside the index

The index holds tokens with their metadata and signals, not pages. Retrieval runs on posting lists and on embeddings, and AI Overviews and AI Mode use the same index and the same snippets.

Stage Each page's tokens are stored as they are, with their metadata: "we don't have the full content of the page in our index" (not in docs). Nearly every signal calculated for a document, such as quality, country and language, is attached to it.

Stage Posting lists, a structure at least 60 years old, list for most tokens the URLs that contain them; the lists of a query's important words are intersected into unranked candidates (not in docs). Docs Google's explainer simplifies this to "an entry for every word".

Stage "just like you build a posting list, you can also build a vector space": the distance between embeddings of document parts and of the query decides what comes back. Both routes work from page content, so "this mantra that we started 25 years ago or whatever still stands, whether we like it or not".

The same index, the same snippets for AI answers

Stage "the snippet that you see was reconstructed from these tokens" (not in docs). AI Overviews and AI Mode use those same structures and snippets: fan-out queries go to the Search index and come back with snippets that feed the answer. Docs nosnippet and max-snippet govern that use.

Analysis If a page never appears as a source, check indexing, snippet rules and the Search generative AI setting first. Name the subject in the words people search with and explain it fully; keyword variations add nothing.

Section 13 · Take it back to the office

Day 2 action checklist

Seventeen checks that turn Day 2 into work. Most need URL Inspection, a crawler and a look at your templates.
Rendering and indexing controls
  • Title, canonical, robots meta, main text and links are in the HTML the server sends
  • Tab content is in the initial DOM, lazy loading fires on viewport entry, long lists have paginated links
  • robots.txt on every host (site, API, CDN) allows the scripts and endpoints rendering needs
  • Pages to keep out are crawlable and carry noindex in the server HTML
  • max-snippet:-1 and max-image-preview:large on indexable templates; snippet limits weighed as AI limits
Duplicates, canonicals and site moves
  • Redirects, rel=canonical, internal links, sitemaps and hreflang all name one preferred URL
  • Canonical groups: one hop, no loops, one canonical per page, an indexable and linked leader
  • Bot challenges reach crawlers as a 503; empty variant combinations return 404
  • Every moved URL has an approved same-intent destination; removed URLs return 404 or 410, never the homepage
Content, markup and media
  • Ranking terms sit in the title, headings and opening text; no hidden keyword blocks remain
  • One page per template passes the Rich Results Test without duplicate types; duplicates carry the same markup
  • Images that should rank use img with a real src; key videos have their own watch page and markup
  • Watch pages load the player in the first viewport without a click, and carry no noimageindex
International
  • hreflang: self-reference, return links, one method, codes validated against ISO 639-1 and 3166-1
  • Templates are translated with the main text; the language selector uses plain <a href> links
Index selection and measurement
  • Not-indexed URLs are compared with indexed pages of the same type, not resubmitted again and again
  • Trends lines are read as shares; volumes come from Search Console or keyword tools
