Thing · Concept

Redirects

Answers that send crawlers and users from one URL to another, server-side (permanent 301 and 308, temporary 302 and 307) or with JavaScript; a strong canonical signal and the core of a site move.

ConceptAlso calledredirect, redirected, redirecting, permanent redirect, permanent redirects, temporary redirect, temporary redirects, 3xx, 301, 302, 307, 308

DocsSourceD2-C357

Google's redirects guide says Google keeps track of both the source and the target of a redirect: one becomes the canonical, depending on signals such as whether the redirect is permanent or temporary, and the other becomes an alternate name that may appear in results when a query suggests the user trusts the old URL more. After a move to a new domain, old URLs may still show occasionally; the guide calls this normal.

AnalysisD1-C421

Of the two answers a community speaker offered for a request to a URL variant (redirect, or an error page), Google's canonicalization guide favours the redirect: a redirect is a strong signal that its target should become canonical, while an error page throws away any links pointing at the variant.

Google's redirects guide says Google Search follows JavaScript location redirects only after rendering, may never see one if rendering fails, and should be used only when server-side or meta refresh redirects are impossible; its site move guide asks for server-side permanent redirects (301 or 308) where technically possible. The JavaScript in Google's own migration was a fallback ('my only option'), not a pattern to copy.
